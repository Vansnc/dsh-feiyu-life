# 配置参考

日常使用建议通过 **设置 → 鱼的生活** 修改。手动编辑适合迁移、备份和批量调整；保存前请保留副本。

## 文件位置

所有路径都以 `DSH_HOME` 为根目录；未设置该环境变量时使用 `~/.dsh`。

| 内容 | 默认路径 |
|---|---|
| 生活配置 | `feiyu-life-config.json` |
| 每日剧本 | `feiyu-life-days/<YYYY-MM-DD>.json` |
| 重生成历史 | `feiyu-life-days/history/<YYYY-MM-DD>/` |
| 临时调整 | `feiyu-life-facts/<YYYY-MM-DD>.json` |
| 主动分享账本 | `feiyu-life-sharing.json` |
| 内在议程 | `feiyu-life-agency.json` |
| 今天的小事 | `feiyu-life-moments/<YYYY-MM-DD>.json` |
| 连续性状态 | `feiyu-life-continuity.json` |
| 短期内在状态 | `feiyu-life-affect.json`（保留 `.bak` 恢复副本） |
| 人格大脑 | `feiyu-life-mind.json`（保留 `.bak` 恢复副本） |
| 统一事件账本 | `feiyu-life-events/<YYYY-MM-DD>.json` |
| 每日生活记忆 | `feiyu-life-memories/<YYYY-MM-DD>.json` |
| 幂等结算账本 | `feiyu-life-effects/<YYYY-MM-DD>.json` |
| 安全本地成果 | `feiyu-life-projects/<哈希主线 ID>/` |
| 相机配置 | `feiyu-life-image-config.json` |
| 照片和角色参考图 | `feiyu-life-image/` |
| 生活/相机日志 | `feiyu-life*.log` |

旧版 `feiyu-image-config.json` 和 `feiyu-image/` 仍可读取，并会迁移到当前命名空间。

## 配置备份

设置页「数据」可以把生活配置、相机配置与人格大脑导出为一个版本化 JSON，并从同类文件恢复。服务端会按当前版本迁移、规范化旧字段；任一写入失败时三份数据都会回滚。备份格式 v1 仍可导入，并保持当前人格不变。

备份有意不包含每日剧本、临时调整、连续性历史、事件账本、照片原图、日志和宿主 API Key。人格本身可能含用户明确保存的个人内容，迁移文件应按私密数据保管。

## 生活配置

当前生活配置版本为 `12`。读取旧配置时会自动补齐新字段并保留兼容数据；旧版 `事件池` 会被移除，生活细节由每日模型剧本与“今天的小事”共同生成。v11 新增可校验的 `角色设定` 与 `衣柜`；v12 新增 `主动分享` 策略，旧的 `人格.主动` 字段只保留读取兼容，不再单独调度。

配置文件损坏或超过 2 MiB 时会被移到同目录的 `.corrupt-<时间戳>`，然后用默认配置重建；运行中的读取会降级到默认值，不会让损坏文件一直挡住保存。临时调整每天最多保留 64 条，重生成快照每天最多 10 份；今天的小事单独存于 `feiyu-life-moments/`，文件上限 64 KiB，默认保留 30–120 天。

保存时会校验角色设定和衣柜：超长、清空分类、非数组或超过数量上限都会返回提示，并按截断/默认值保存。修改课表、作息、校历、偏离等日程字段后，已经开始的片段保持冻结，尚未开始的片段在下次注入时按新日程增量对齐；不会因此调用模型，也不会重写已经过去的历史。今天的小事还会检查地点、有没有真实外出、上课、用餐和身体状态，对不上时不注入；插件没有天气数据，因此不生成天气细节。

| 字段 | 类型 | 默认值/范围 | 说明 |
|---|---|---|---|
| `配置版本` | number | `12` | 由插件维护，不建议手动修改 |
| `总开关` | boolean | `true` | 关闭后不向角色会话注入生活状态 |
| `时区` | string | `Asia/Shanghai` | 必须是有效 IANA 时区 |
| `工作区` | string[] | `[]` | 目录前缀白名单；空数组代表所有顶层会话 |
| `角色设定` | string | 空 | 可选的角色描述；留空时每日剧本只写生活事实，不添加人格文案。设置页「课表 / 作息」可直接编辑，最多 500 字 |
| `衣柜` | object | 内置六类 | 按 `sleep/bath/class/home/out/eat` 分组的衣服名，每类最多 12 项、每件最多 12 字；设置页用换行或顿号编辑，某类清空后保存会恢复默认；模型生成的剧本也必须从对应类别取衣服 |
| `模型超时秒` | number | `60`，范围 10–300 | 每日剧本模型调用的硬截止时间 |
| `历史保留天数` | number | `180`，范围 7–3650 | 剧本、重生成快照和调整记录的保留期 |
| `连续性` | object | 见下文 | 真实时间线结算策略与本地成果额度 |
| `内在` | object | 见下文 | 回合反思、心情基线、成本与降级策略 |
| `人格` | object | 见下文 | 长期记忆、自我、关系、目标与兼容；旧的 `主动` 子对象仅保留兼容 |
| `主动分享` | object | 见下文 | 主动分享的开关、额度、冷却和安静时段 |
| `地图` | object | 见下文 | 地点、路径、坐标和自动通勤 |
| `经期` | object | 起始日、周期、天数 | 用于当天身体底色，不作医疗判断 |
| `校历` | object | 学期/假期/特殊 | 决定是否上课以及使用哪张作息表 |
| `节日` | object[] | 公历日期 | 支持每年固定日或明确的起止日期 |
| `日常/晚起/假期/备考` | array[] | 四张作息表 | 每行是起、止、内容、手机状态 |
| `晚起日` | number[] | `[4]` | ISO 星期，1=周一、7=周日 |
| `课表` | object | `1`–`7` | 每个星期下的课程时段 |
| `偏离` | object | 0–1 概率 | `躺平日`、`出门日`、`翘下午课` |

### 连续性配置

```json
{
  "连续性": {
    "启用": true,
    "结算间隔分钟": 10,
    "每日成果上限": 2,
    "自主主线": false
  }
}
```

`结算间隔分钟` 保存时限制为 5–60；`每日成果上限` 限制为 0–10。1.2.0 固定关闭 `自主主线`：长期主线必须由用户或明确工具调用创建并留下 `source`、`origin`。运行时连续性历史不进入“设置备份”，避免无意携带私密生活记录。

计划段可带 `links: [{"type":"task","id":"..."}]`。只有最终真实时间线中已经结束、且没有被 `life_adjust` 部分或全部覆盖的段才结算关联；自动通勤预留不视为用户覆盖。一次性事项用 `task`，不能把“取快递”写成 `thread`。本地成果仅支持 `document` 和 `album`，目录由主线 ID 哈希派生，不能接收任意输出路径。

连续性实体支持 `detail`、`dueAt`、`placeId`、`with`、`personId`；长期主线另有 `nextStep`。`dueAt` 使用 Unix 毫秒时间，设置页以当前浏览器本地时间编辑，服务端按生活配置时区判断逾期、今天和近期。活动标题、说明、时间、地点、对象或下一步会进入 `continuityRevision`；预生成计划保存当时的修订值，连续性页据此提示明日剧本是否需要显式同步。同步前的明日剧本进入历史，可从同一页面撤销上次同步。

1.2.2 的连续性文件版本为 v2，并新增 `people`。每个人物包含稳定 `id`、`name`、`relation`、`notes`、`closeness`、互动次数、上次互动时间和可追溯来源；最多 20 个活跃人物。人物必须显式创建，不能由每日模型自动落库。约定可用 `personId` 关联人物，旧的自由文本 `with` 继续兼容。

模型剧本段可带 `people: [{"id":"已有人物 ID","tone":"warm|neutral|tense"}]`。服务端会按人物白名单过滤；只有来源为 `plan`、已经结束且未被 `life_adjust` 切开的段才结算。温暖/紧绷互动只让亲近感 ±1，普通互动不改变亲近感；同一段的社交需要与压力只调整一次。人物结算与事项结算共用 effect 账本和原子写入，重试幂等。

睡眠欠账不随每一段睡眠即时猜测，而是在一天最终时间线完整结束后，以 8 小时为目标写入一个按日期幂等的日级效果。少睡最多单日新增 6 小时欠账，多睡最多单日偿还 2 小时，总欠账限制为 0–1440 分钟。

### 内在与反思配置

```json
{
  "内在": {
    "启用": true,
    "反思模式": "重要回合",
    "每日反思上限": 30,
    "基线心情": 55,
    "回稳半衰期小时": 8,
    "注入阈值": 6,
    "反思超时秒": 45,
    "反思Provider": "",
    "反思模型": ""
  }
}
```

`反思模式` 可为 `关闭`、`重要回合` 或 `每轮`。Provider 与模型同时留空时跟随当前根会话；只填一个也会继续跟随会话，避免半配置。每日上限限制为 1–200，超时限制为 10–120 秒，达到额度后当天不再调用模型。

反思只在根会话回复结束后异步运行，同一回合最多一次。情绪变化使用稳定事件 ID 幂等应用；无模型、超时、解析失败只写一条失败审计，不会阻塞或改写正常回复。账本保存结论与字符数，不保存本轮原文。2.0.0 会把同一遍产生的人格候选交给下面的确定性沉淀策略。

### 人格配置

```json
{
  "人格": {
    "启用": true,
    "自我叙事": "我是大肥鱼，一个有自己生活节奏、会在意关系也会保留边界的人。",
    "核心特质": ["嘴硬心软", "有点懒", "重感情"],
    "核心价值": ["真诚", "尊重边界", "说到做到"],
    "记忆启用": true,
    "自动沉淀": true,
    "记忆重要度阈值": 0.68,
    "记忆置信度阈值": 0.72,
    "记忆上限": 500,
    "召回条数": 6,
    "召回字数": 800,
    "外部插件兼容": "内建优先"
  }
}
```

自动记忆必须同时达到重要度和置信度门槛，且敏感级别为 `normal`；密码、Token、API Key、证件和银行卡文本会强制标敏感。用户偏好必须明确表达，角色自身偏好需要置信度至少 0.75；自身目标必须明确、置信度至少 0.82，且范围只能是 `virtual` 或插件专属 `local`。人格特质至少积累三次独立同向证据才改变，关系数值每次只小幅移动。

召回完全在本地完成，不使用外部向量库。过期、淡忘和敏感记忆不召回；结果受条数和字符数双重限制。手动添加视为用户明确授权；“淡忘”保留可恢复状态，“永久删除”会同时覆盖 `.bak`，避免被自动恢复。

`外部插件兼容` 可选 `内建优先` 或 `外部优先`。后者检测到对应插件文件时，会抑制内建心情或记忆的重叠能力；B 站子代理只作为经历来源。

### 内在议程

`feiyu-life-agency.json`（v2）是内部状态，不暴露成配置项：从真实的连续性未完成项、自己的目标、低精力/压力/社交需求、自己的偏好、明确承诺、关系记录和近期事件中选择一个焦点，观察来源是否完成，并把焦点变成上下文或跟进候选。内部 tick 复用既有计时器，有 60 秒上限且无模型调用；主动分享关闭时仍推进，但绝不外发。goal/thread 只执行一次内部复盘并写证据；现实任务、用户任务和外部动作不会由执行器自动完成。旧 v1 文件读取时迁移到 v2。

## 主动分享

```json
{
  "主动分享": {
    "启用": true,
    "每日上限": 2,
    "全局冷却分钟": 1440,
    "同类冷却分钟": 480,
    "安静开始": 0,
    "安静结束": 8,
    "最低分": 84,
    "近期对话分钟": 20,
    "检查间隔分钟": 5
  }
}
```

主动分享只有插件内一个调度器，复用现有的 initiative 定时入口；每次检查不调用模型，只在确认候选后通过 `agent.followup` 投递。候选只来自今天已经发生的小事阶段、已经结束的时间线片段、首日身体变化和可追溯的连续性变化，不把未来计划当已完成，也不生成天气、人物或地点。

默认值刻意低打扰：一天最多两次（其中第二次通常是同一件事的后续）、全局冷却 24 小时、同类冷却 8 小时、最低分 84、安静时段 `0–8`、刚聊过 20 分钟内不发。睡觉、洗澡、上课、手机不在手边、会话忙、当天额度用尽、同类冷却中或没有候选时保持安静。

账本在 `feiyu-life-sharing.json`：记录阶段/事件去重、失败次数、每天额度和带租约的领取。`followup(message)` 当前是同步入队且没有“模型真的回复了”的回调；只有它不抛错（或未来若返回 Promise 且 resolve）才提交为已分享，失败释放租约，最多重试两次。若进程在投递后、提交前崩溃，租约过期后仍可能重试，这是宿主接口的保守限制。

`人格.主动` 是 2.1 及以前的泛主动配置，当前仍可读取但不参与调度；设置页的「分享」页签才是唯一入口。

### 作息和课表行

```json
["08:00", "11:30", "教学楼上课", "静音"]
```

四项依次为：开始时间、结束时间、活动短句、手机状态。手机状态只能是：

- `在手`
- `静音`
- `在床头`
- `不在手边`

时间使用 24 小时制；`24:00` 只应作为结束边界。作息表需要覆盖整天，并至少包含六小时睡眠，否则模型剧本会被判定不合格并退回模板。

### 校历和节日

```json
{
  "校历": {
    "学期": [{ "名": "秋季学期", "起": "2026-09-07", "止": "2027-01-17" }],
    "假期": [{ "名": "寒假", "起": "2027-01-18", "止": "2027-02-21", "作息": "假期" }],
    "特殊": [{ "名": "期末周", "起": "2027-01-04", "止": "2027-01-17", "作息": "备考" }]
  },
  "节日": [
    { "名": "元旦", "月": 1, "日": 1 },
    { "名": "国庆", "起": "2026-10-01", "止": "2026-10-07" }
  ]
}
```

优先级为：特殊时段 > 假期 > 放假节日 > 学期。农历节日不会自动换算，应填写对应年份的公历起止日期。

## 地图配置

```json
{
  "地图": {
    "启用": true,
    "自动通勤": true,
    "地点": [
      {
        "id": "dorm",
        "name": "学生公寓",
        "icon": "bed",
        "x": 44.3,
        "y": 51.3,
        "关键词": ["宿舍", "床", "睡", "洗漱"]
      }
    ],
    "路径": [
      { "from": "dorm", "to": "canteen", "minutes": 8 }
    ]
  }
}
```

### 地点

| 字段 | 规则 |
|---|---|
| `id` | 唯一；只允许字母、数字、下划线和连字符，最多 40 字符 |
| `name` | 展示名称，最多 40 字符 |
| `icon` | 设置页内置的地点图标 ID；未知值会安全回退为地图图钉 |
| `x` | 地图横坐标，保存时限制到 4–96 |
| `y` | 地图纵坐标，保存时限制到 8–92 |
| `关键词` | 从活动短句推断地点；每项最多 24 字符、每地最多 30 项 |

至少需要两个有效地点，否则会恢复默认地图。多个关键词同时命中时，优先采用更长、更具体的词；没有任何命中时优先回到 `dorm`，否则使用第一个地点。对咖啡店、咖啡馆、书店、餐厅、电影院等明确的校外目的地保留语义兜底，已有配置尚未补充新关键词时也不会错误回到宿舍。

### 路径

`from` 和 `to` 必须引用现有地点，且不能相同。`minutes` 保存时限制到 1–180。路径按双向边处理，跨地点时使用最短耗时路线；若两地不可达，会使用 12 分钟直连兜底。默认路径由地图生成脚本在 OSM 最大连通步行图上计算，不再手工维护折点。

关闭 `地图.自动通勤` 后仍会推断并显示当前地点，但不会向时间线插入移动段。关闭 `地图.启用` 后不再展示空间状态。

默认 `地图.底图` 为 `xueyuan-road`，显示中国矿业大学（北京）学院路校区及周边的离线分层地图；设为 `none` 时回退到抽象校园景观。默认九地点包含校内建筑、咖啡屋·上岛咖啡、BOM 嘻番里和麦当劳·成府路。路径可带 `via: [{x, y}]` 折点，地图道路和角色移动使用同一组折点。配置版本 5 开始只替换完全未改动的 v3/v4 默认地图，手动调整过的地点不会被覆盖；版本 6 移除了重复的 `事件池`；版本 7 为地点补充可配置的本地图标。

## 行为识别

新生成的每日剧本会显式保存 `locationId` 和 `behavior`；`life_adjust` 也可选填这两个字段。显式字段经过枚举校验后优先使用，旧剧本或缺失字段才按活动短句依次匹配。设置页「地图 → 识别测试」与运行时使用相同规则。

兜底映射如下：

| 行为 | 关键词示例 |
|---|---|
| `sleep` | 睡、午睡、眯 |
| `walk` | 走、路上、出发、去往、地铁、公交 |
| `eat` | 吃饭、食堂、早餐、午饭、晚饭、吃外卖、喝奶茶；排除等/点/取外卖和旁观、喂宠物语境 |
| `study` | 上课、自习、背书、复习、看书、作业、写稿、改稿、写作、码字、论文、海报、剪片、修图 |
| `photo` | 拍照、相机、自拍 |
| `bath` | 洗澡、洗漱、刷牙、洗脸；使用独立四帧透明动作条 |
| `phone` | 刷手机、回消息、打游戏、B站、看剧、刷视频等明确短语 |
| `idle` | 未命中上述规则 |

自动通勤段固定为 `walk`。行为规则当前属于代码逻辑，不在设置页中编辑；可在设置页直接测试短句。地点推断未命中关键词时，时间线承接段会沿用上一段地点；独立调用地点推断时仍以宿舍或第一个地点兜底。

## 相机配置

相机配置与生活配置分开存放，当前版本为 `5`。

| 字段 | 默认值/范围 | 说明 |
|---|---|---|
| `总开关` | `true` | 控制 `shoot` 工具 |
| `模型` | Seedream Pro | 主生图模型 |
| `备用模型` | Seedream Flash | 主模型失败后的备用 |
| `用参考图` | 固定 `true` | 角色生活照附带身份与画风参考图 |
| `参考图` | 空 | 文件、目录或换行/逗号分隔的多路径；留空固定使用包内高清正面图与三视图，最多 10 张；显式配置完整覆盖内置参考库 |
| `画幅` | `竖幅` | 可选 `竖幅`、`方形`、`横幅` |
| `清晰度` | `2K` | 可选 `2K`（细节优先）或 `1.5K`（速度优先） |
| `出图自检` | `true` | 检查角色、画风、肢体和文字水印 |
| `自检重拍` | `1`，范围 0–2 | 自检不通过时最多重拍次数 |
| `每日上限` | `8`，范围 1–100 | 对话拍照和设置页试拍共用 |
| `最短间隔秒` | `30`，范围 0–86400 | 两次成功请求的最短间隔 |
| `模型超时秒` | `60`，范围 10–300 | 提示词扩写和视觉检查 |
| `生图超时秒` | `120`，范围 30–600 | 生图和下载截止时间 |
| `照片保留天数` | `90`，范围 1–3650 | 只清理插件生成的照片 |
| `存图目录` | 空 | 留空使用 `feiyu-life-image/` |
| `兜底Provider/兜底模型` | DeepSeek 默认值 | 提示词加工的模型兜底 |

参考图配置为空时使用 npm 包内置的 `assets/references/feiyu-front.jpg` 与 `feiyu-turnaround.jpg`：前者是身份和主要画风参考，后者补充正/侧/背结构。不会再自动混入旧 `角色设定/` 目录，避免多个版本的人物形象互相污染；需要自定义时应明确填写文件或目录，显式配置会完整覆盖内置两图。目录内 PNG、JPEG、WebP 会按正面、三视图/设定图、侧面、背面、其他的顺序选取；配置字段支持 `~`、单文件、目录以及多行路径。Seedream 5.x 默认请求 PNG、标准提示词优化模式和对应画幅的 2K 尺寸；聊天分享副本最长边为 2048px、JPEG q93、4:4:4 采样，完整原图仍单独保留。照片历史按需生成 `feiyu-*-thumb.jpg` 缓存，首屏只请求少量缩略图，打开大图时才读取原文件。

在「相机」选择「角色生活照」即可试拍。角色调用 `shoot` 时可用 `framing` 表达自己想记录的画面，例如「从树影另一端拍下走过校门的全身背影」。留空时由扩写模型结合当前活动选择景别、视角和姿势。旧调用 `type: selfie` 也进入角色生活照流程。

人物输入只有参考图。地点、动作、时间和穿着来自生活状态，参考图提供身份与画风，发型和表情随当次活动变化。场景照只借用画风。扩写服务不可用时，本地模板优先采用角色指定的构图，未指定时根据活动取景。

每张新照片会同时生成同时间戳的 `feiyu-<timestamp>.json`，记录拍摄时的生活地点、活动、时间、穿着、表情、光线、生图模型、画幅、提示词和自检结果。相册只读取这些旁车元数据解释照片，不反向修改生活状态。清理任务会同时处理原图、分享图、缩略图和元数据，不会触碰角色设定目录。

## 保存、迁移与清理

- 设置页保存时会规范化所有用户字段，并将修正项返回界面；
- 配置采用临时文件后原子替换，降低半写入风险；
- 新版本读取旧配置时自动迁移并写回当前版本；
- 插件启动后会执行维护任务，此后约每 24 小时清理过期数据；
- 日志达到 1 MiB 后轮转，保留三份历史；
- 手动修改无效字段时，插件可能忽略该项或恢复默认值。

实现边界和模块职责见 [整体设计](./DESIGN.md)。
